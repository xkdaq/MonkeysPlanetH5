2. **key/iv 复用**：key=`47ccmuRaEWyYFmVn`，iv=`K5i9TbRSthzaQ5Hm`（与 H5 文章/首页/资料接口共用的一组；注意 ruoyi-mp 的 `EncryptedResponseAdvice` 用的是另一组 iv=`K5i9TbRSthzyaQ5H`，别搞混）。
3. **前端**：`public/html/333/大转盘.html` 新增解密工具：用**浏览器原生 Web Crypto API**（crypto.subtle AES-CBC，零依赖，比引 CryptoJS 库更隐蔽）；`_parseBody()` 先按明文 JSON.parse 尝试（兼容新旧后端、部署过渡期不挂），失败再 `_aesDecrypt` 解密后 parse。两处 fetch（banks/questions）均改用 `_parseBody`。

注意：Web Crypto API 的 AES-CBC 默认 PKCS7 padding，与 Java 端 PKCS5Padding 对 AES-128 完全兼容（已验证）；crypto.subtle 仅在 https 环境可用（api/study 都是 https，无影响）。

## 2026-08-21 接口加密返回被 Jackson 加双引号修复

问题：部署后前端仍显示"加载失败"。curl 实测 `api.monkeysxu.top/h5/wheel/banks` 返回 `Content-Type: application/json`，body 是带外层双引号的 JSON 字符串 `"nuTSd5WZ..."`，导致前端 `atob('"nuTS..."')` 失败。

根因：`WheelH5ResponseBodyAdvice` 返回 String 后，Spring 选用了 Jackson converter，把 String 当作 JSON 字符串又序列化了一次，加了外层双引号。

修复：`beforeBodyWrite` 改为手动写入 `response.getBody()`（Content-Type 设为 `text/plain`），然后返回 `null`，跳过 Spring 后续 converter 处理。这样响应体就是 raw Base64，前端直接解密。

验证：本地用 node 模拟 Java 加密 + Web Crypto 解密闭环已通过；JAR 重新打包待部署。
